# 诊断系统（编译期与运行期报错）

> 第 29 轮（2026-11-01）重写。目标：**无效源码必须报错，报错必须能定位，定位必须能一键跳转**。

## 一、输出格式

所有诊断走同一套渲染（`diagnostic` 包），样式对齐 rustc：

```
━━━ 发现 1 个问题（1 个错误） · 词法/语法 · demo.hy ━━━
✘ 根因 [E010]: 代码块未闭合：第 1 行的 '{' 直到文件末尾（第 3 行）都没有对应的 '}'
   --> demo.hy:1:9（行 1, 列 9）
     |
   1 | 函数 f(a) { 返回 a
     |         ^ 在代码块结束处补上 '}'
```

要点：
- 首行摘要带**阶段**（词法/语法 / 类型检查 / 静态检查 / 运行期）与**文件名**；
- 每条诊断有 `文件:行:列`（机器可读，编辑器/CI 可直接跳转）＋ 人读的行列描述；
- 源码片段下方的箭头按**显示宽度**对齐（中文算 2 列，不会错位）；
- 同一处问题的多个症状用因果链表示（`根因` → `连带` → `↑ 因:`），不再重复整块输出。

## 二、错误码

| 段 | 范围 | 内容 |
|---|---|---|
| 词法/语法 | E001-E015 | E007 字符串未闭合 · E010 代码块未闭合 · E011 括号未闭合 · E012 方括号未闭合 · E013 重复形参 · E014 循环外 跳出/跳过 · E015 与内置同名 |
| 类型/静态 | E101-E106 | E101 类型不匹配 · E102 未定义标识符 · E103 参数数量 |
| 运行期 | E201-E210 | E201 未定义标识符 · E202 除零 · E207 索引越界 · E209 哈希键不存在 |
| 模块 | E301-E305 | E301 文件读取/不存在 · E303 导入文件语法错误 |

> LLVM 后端对索引/调用/转换类还有更细的 E2xx 细分码（E205 索引类型 · E206 不可调用 · E213-E225 内置函数参数校验），
> 与解释器同名错误的码值已对齐（除零 E202、取模零 E203、运算符不支持 E204、越界 E207、缺键 E209、溢出 E210）。

## 三之前、机器可读诊断（`-c --json`）

`zuzo -c --json <文件.hy>` 在 **stdout** 输出一个 JSON 数组，供编辑器 / CI / 测试脚本直接消费：

- 永远是数组：**零诊断输出 `[]`**（不是空输出，也不是 `null`）；
- 每个元素固定 7 个字段，字段永远存在、类型固定：
  `code`（错误码，缺失归一化为 `E000`）· `file` · `line`（1 起；0 表示无位置）· `col`（1 起）· `message` · `suggestion`（无建议时为空串）· `severity`（`error` / `warning` / `note` / `info` / `unknown`）；
- 顺序稳定：按行、列、错误码排序；同一位置保持原始因果顺序（稳定排序）；
- **人读报告不进 stdout**：树形报告与「✓ 类型检查通过」一律写 stderr，stdout 只有 JSON。

```bash
$ ./zuzo.exe -c --json --strict tmp/r30/type_invalid.hy 2>/dev/null
[
  {
    "code": "E103",
    "file": "tmp/r30/type_invalid.hy",
    "line": 2,
    "col": 6,
    "message": "参数数量不匹配: 期望 2-3 个参数，得到 1 个",
    "suggestion": "",
    "severity": "error"
  }
]
$ ./zuzo.exe -c --json tmp/r30/type_valid.hy 2>/dev/null
[]
```

契约实现见 `diagnostic/json.go`（字段顺序即文档承诺顺序），回归见 `diagnostic/json_test.go`。

## 三、三档检查强度

| 模式 | 命令 | 行为 |
|---|---|---|
| 默认 | `zuzo a.hy` | 语法/词法错误阻断；类型与静态问题**警告**（不阻断执行）；运行期越界/缺键**警告并返回空** |
| 严格 | `zuzo --strict a.hy` | 类型/静态问题视为编译错误；运行期越界/缺键直接报错（`--emit-exe --strict` 同样生效） |
| 只检查 | `zuzo -c a.hy` | 不执行，做语法 + 类型 + 静态检查（未定义标识符、导入文件存在性、字面量除零、与内置同名） |

## 四、静态能提前发现什么

`-c` 与运行时启动都会跑（`analyze` 包）：

1. **未定义标识符**（E102）——全文件从未定义且不是内置。口径保守：只要文件任意位置定义过（含被导入文件的顶层定义）就放行，宁可漏报不误报。实测在 `examples/` + `tests_llvm/` + `projects/` 上零假阳。
2. **导入文件不存在**（E301）——按 `路径`、`路径.hy`、`路径.z` 三种形式查找。
3. **字面量除零/取模零**（E202/E203）。
4. **与内置函数同名**（E015）——解释器用你的版本、LLVM 产物用内置，两条链会不一致，这是最难查的一类坑。

## 五、运行期诊断

- 数组/字符串越界、哈希缺键默认 **返回空 + stderr 警告**（保持既有语义，不破坏老程序）：
  ```
  ⚠ 运行期警告 demo.hy:2:7 [E207]: 数组索引越界: 10（长度 3，有效范围 0..2，负值从尾部计）（本次按「空」继续）
  ```
- `--strict` 时升级为错误并中止，退出码 1。
- 环境变量 `ZUZO_RT_WARN=0` 可关闭运行期警告（对拍脚本用它保持输出纯净）。
- 内置函数报错时自动补上**调用点**行列（此前只有消息没有位置）。

## 六、索引语义

- 数组与字符串都支持**负下标**（从尾部计），越界仍按第三/五节的档位处理。
- 字符串下标按 **UTF-8 码点**计（`"中文abc"[1]` = `"文"`），与 `长度()` 的口径一致。

## 七、已知边界

1. 类型推断仍有假阳（如内置函数带默认参数、`哈希 == 空` 的比较），因此类型问题默认只警告；`--strict` 下可能误伤。
2. `执行/遇到`（try/catch）在解释器与 LLVM 后端产物上均已生效，捕获**运行期**错误对象（E2xx）；编译期诊断（E0xx / E1xx）不受 try 影响，仍然直接失败。两处口径差异：LLVM 产物的错误值是字符串载体，`字符串(e)` 得到 `错误 E202: 除零错误`（解释器为 `运行错误 [E202] 行 N: 除零错误`）；`错误行(e)` 在 LLVM 产物固定返回 0（编译产物不携带行号）。
3. LLVM 后端与解释器在内置同名、重定义函数等边角语义上仍可能不一致（见 `tmp/r29/consistency.md` 的分歧清单）。
